Lab 19–22a — Fixed Point and Affine Quantization, by Hand

Lab thesis: every int8 or int4 format is an integer plus an agreed scale. This lab has you build the two maps from the lectures yourself, fixed point with its power-of-two scale and affine with any scale and a zero-point, and then explain the choices each line of your code makes.

This is the build half of Lecture 19/20 — Number formats and Lecture 21/22 — Affine quantization. Lab 19–22b then measures what these quantizers do to a signal and to a model.

You work in GitHub Codespaces, in the browser, with nothing to install. Each Codespace opens on its exercise file with pytest ready.

Exercise Open You fill in
Fixed point (Lecture 19/20 §2) code/quantization/fixed_point/fixed_point.py, TODOs A–F
Affine (Lecture 21/22 §1–§4) code/quantization/affine/affine_quantizer.py, TODOs A–F, and G (stretch)

What you do

  1. Fill in the TODOs in order. Each exercise's README.md lists them; each TODO comment says what to compute.
  2. Run pytest -q after each TODO. The test names start with the TODO they check. These are self-checks: they tell you that you are on track, and they are not what you are marked on.
  3. Answer the seven questions in code/quantization/lab19_22a_answers.md. Copy it into your Codespace, fill in your roll number and name, and write 3–6 sentences under each question.

What you submit

One zip, named <roll>.zip, with exactly three files:

File From
fixed_point.py your filled-in fixed-point exercise
affine_quantizer.py your filled-in affine exercise
answers.md the answers template, filled in

Keep the file names, class names and function signatures as given. The marking script imports them by name.

How it is marked

Automatic, 60 marks: a hidden test suite. Your two files are run against about 50 tests you have not seen. They use other Q-formats (Q1.6, Q5.2, Q0.7, 16-bit), other bit widths (2, 3, 4 and 16 bits, signed and unsigned), data that does not span zero, ties in both directions, saturation at both ends, and random inputs checked against a reference. Passing the self-checks does not guarantee passing the hidden tests. Code that follows the lectures' equations does; code fitted to the self-checks' numbers does not.

Marks are per TODO, in proportion to the hidden tests for that TODO that you pass:

fixed_point.py Marks affine_quantizer.py Marks
A — scale 3 A — integer grid 4
B — range 4 B — stretch to include 0.0 5
encode 4 C — scale 3
C — saturate 4 D — zero-point 6
addition 4 E — quantize 8
D–F — rounded multiply 9 F — dequantize 6
Total 28 Total 32

TODO G (the four-term dot product) earns up to 4 bonus marks on top of the 60.

Rubric, 40 marks: answers.md. Each answer is marked on naming the mechanism (saturation, rounding bias, range against step, the zero-point) and on pointing to your code or to a number you printed. The marks per question are in the template; the heaviest are Q2, rounding bias and Q6, why zero must be exact.

The automatic half is marked by code/quantization/grade_lab19_22a.py.

Academic integrity

Correct code for these TODOs is short, and two honest solutions often match line for line. That is expected and is not penalised. The answers are yours to write: identical answers.md files are flagged as copied. Discussing mechanisms is encouraged; sharing files is not.
